# Acceptance quality

Define the intended outcome before tasks. Encode root/stage/task relationships,
mandatory coverage and explicit REQUIRES_GOAL_PASS consumption gates. Wave is
scheduling and TEST_LEVEL is evidence maturity. Preserve root scope and quality
floor; a finalizer cannot require its own parent already complete.

ACCEPT names source/input version, parameters, output/schema, completeness,
quality and falsifier. TEST names an executable scope-appropriate Run and required
evidence. CLI checks do not prove native execution or GUI evidence. Retained
sourceRefs are inherited policy; new criterion_origin=derived criteria record
source anchors, rule, reason, falsifier, grant and independent reviewer.

Keep frozen-progress, single-source grant/stale and inherited-versus-derived
criteria regressions. Current endpoint acceptance uses real spec/goal/apply,
actual planning adoption, two nonconflicting native workers with observed overlap,
and independent verification/closure. No mandatory multi-variant x3 or ablation.
Do not interpret source authoring, strict validation or old PASS as runtime success.
